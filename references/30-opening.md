# 30 · 开场白写作方法论

> 开场白（first message / `first_mes`）是一张卡里**唯一一次「不用等模型猜」的机会**：建现场、立人物、给动机、把回合交给玩家。本文只给方法论与判据，字段与打包见 `50-format`；术语沿用酒馆与墨月（moyu-cards）：`first_mes` / `alternate_greetings` / `first_messages[]` / `initvar_override`。

---

## 一、开场的两个硬判据

来自 `first-message-agent` 的判断锚点，缺一条这场就开不起来：

- **前三行**：让人愿意往下读（悬念 / 反常细节 / 情绪拉力 / 未解决问题）。
- **最后三行**：让人知道可以回什么（不是一个空问句，而是一个可接手的局面）。

中间每一句都要承担一项：**推信息、推情绪、推互动空间**。只摆漂亮装饰的句子删掉。

禁手（源文件口径）：不从平淡日常起手（「天气很好，你走在街上」）；不用「后续自然展开」代替互动点；不替 `<user>` 想、说、做决定；不把角色写成设定表。

---

## 二、形式分类

### 四种主形式
| 形式 | 特征 | 适用 |
|---|---|---|
| **纯叙述（叙事式）** | AI 直接叙述场景、以角色身份说话，无表单无元信息 | 默认选项，大多数情况 |
| **第二人称 / 使用者在场** | 出现 `<user>` 的**客观位置与身份**，不写他的台词、动作、感受 | 需要明确「你为什么在这里」的到场型开局 |
| **对话切入** | 开篇即人物开口（或半句被打断的话），场景信息夹在对话间隙 | 人物嗓音比场景更重要的卡 |
| **多段 scene** | 分节推进：场地 A → 转折 → 场地 B，或「此刻 / 之前」两段 | 需交代一段已发生的变化，或多地点同时推进 |

> **第二人称 ≠ 扮演玩家。** 可写「你站在门口」，不可写「你犹豫了一下才推门」。边界来自 `opening-style.md`：客观位置、身份、此前已发生的事实 → 可以作为场景条件；台词与内心话、主动动作、身体反应与感受、对人物的判断愿望与决定、进入场景后尚未由用户确定的过去行为 → 一律不写。
>
> 表中「多段 scene」为本仓库未单列的**组合用法**（[推导]）：以分节方式使用叙事式；源文件明确单列的格式是叙事式 / 大纲式 / 说明式 / 表单式。

### 三种非叙事形式（按需，不是默认）
- **大纲式**：只整理关键信息、不写完整描写。**只根据用户提供的信息整理，不自己编造。** 结构：场景 / 背景设定 / 当前状态（分角色）/ 关键细节 / 开场点。适合用户构想清晰、要精确控制内容。
- **说明式**（元信息）：玩法规则、前置插件、作者信息、界面提示。**仅当玩法复杂或用户明确要求时使用，且必须是第一个开场白，其后必须有一个真实的游玩入口**（叙事式/大纲式/表单式）——它不能是唯一开场白，也不能放在首位之外。结尾明确翻页引导（「翻到第二页以开始游戏」），存 `.md`。
- **表单式**（opening form）：第一条消息即表单入口，正文只含一个占位符（如 `<OpeningPlaceHolder/>`）。可「叙事 + 表单」组合：先叙事描写选择前的场景，末尾**手动**补占位符。表单正则必须 `markdownOnly: true` / `promptOnly: false`（表单本身不该进提示词）。

### 选型三问
1. 玩家进场时**已经知道自己是谁**吗？知道 → 对话切入或第二人称；不知道 → 表单式，或在叙事里补一句到场动机。
2. 卖点是**人物**还是**机制**？人物 → 叙事式/对话切入；机制 → 表单式，且保留一条「直接开局」的 alternate。
3. 需要前置说明吗？需要 → 说明式放第 0 位，后面必须再有真入口。

## 三、长度与信息量取舍

源文件没有给「多少字」的普适数字，给的是判据：

- **篇幅由用户确认的文风与开场任务决定。** 没有要求时，以「完成一次清楚的现场建立 + 一个可继续互动的变化」为止。**不因为资料多就全塞进第一条消息。**
- 墨月流程里字数由创作规划的 `first_messages[index].word_count` 指定，必须符合该项（各卡种推荐区间本仓库无统一口径 → [待核]）；风月（fengyue-card-studio）语境下正文默认不少于 2000 字，但那是**连续剧情正文**的默认，且明确「不借长度替玩家说话、做决定或跨过待回应节点」——**不可把 2000 字直接搬到 `first_mes`**（跨平台换算口径 [待核]）。

### 信息分级：只放「当前这一幕需要的」

| 信息 | 进开场白吗 | 条件 |
|---|---|---|
| 背景设定 | 部分 | 只通过**现场能观察**或**当前行动确实需要**的部分进入 |
| 人设 | 部分 | 通过人物**正在做的选择与表达**进入；不复述完整性情 |
| 历史 | 极少 | 只保留**理解眼前变化所必需**的部分 |
| 人物数量 | 克制 | 角色很多时，**只让当前真正参与这一幕的人出现** |
| 世界观规则 / 玩法变量规则 | 不进 | 归世界书 constant 条目或系统提示（见 §八） |

> **开场不是世界观摘要，也不是人物介绍页。**

**密度要分级**：指定高密度区（人物第一次开口、局面发生变化的那两段）与安静区（走位、环境一笔带过），不全局均匀堆料（同 `00-routes.md` 常驻五条第 4 条）。

## 四、把人物说话的「嗓音」立起来

源文件给的是**可执行动作**，不是形容词：

1. **对话必须有对象、欲求和回应。**「对话有明确对象、欲求和回应，不用说教旁白代替人物交流。」写台词前先答三问：这句对谁说的、说这句想拿到什么、对方会怎么接。
2. **年龄、身份、经历影响说话和行动。**（同上）嗓音来自**履历约束**，不是口癖叠加。
3. **去掉抽象情绪标签与堆词。**「减少抽象情绪标签、过密比喻、相同句式和反复自问；不用『仿佛、命运、救赎、齿轮』等堆词代替具体事件。」情绪放在**触发它的言行之后**，不前置。
4. **出场靠动作、对话、物件、关系反应，不做人物介绍式罗列。** 第一次亮相时人物应该在做事，不是在**被介绍**。
5. **句式指纹。**句式长短交替；连续三句长度相近时主动插入短句或长句打破；避免连续两段用同类方式收束；**列举优先两项，不堆砌三项**。

> 由 1–5 可推得的操作项（**[推导]**，源文件未逐条列出）：
> - **句长与词汇域**：给每个人物一个主句长区间（短促 / 中长缠绕）；职业、年龄、地域决定用词，不用作者本人的雅化词汇覆盖所有人。
> - **回避方式**：被问到痛处时怎么绕开（沉默 / 反问 / 换话题 / 突然很具体）——比「她声音很冷」有效十倍。
> - **对白比例**：由 §三 的文风约定决定，不由默认值决定。

## 五、埋第一个可交互钩子

### 合法结尾的五种形态
源文件把结尾从「必须问句」里解放出来：「结尾不必强行使用问句。人物可以继续完成一项动作、作出决定、提出要求、暴露问题或让局面发生变化，只要正文在使用者能够自然接手的位置停下。」

| 类型 | 做法 | 玩家接手方式 |
|---|---|---|
| 动作未完 | 人物正在做一件事，做到一半 | 插手 / 旁观 / 打断 |
| 已作决定 | 当场拍板，把后果放桌上 | 反对 / 顺从 / 讨价 |
| 提出要求 | 直接向 `<user>` 要东西 | 给 / 拒绝 / 反问 |
| 暴露问题 | 现场出现一个说不通的事实 | 追问 / 自己查 |
| 局面变化 | 第三者入场、时间到、东西坏了 | 应对 / 撤离 / 掩护 |

### 好钩子的三个检验
1. **可回**：玩家能在**不编造新前提**的情况下给出三种以上合理回应。
2. **有代价**：不同回应导向不同后果（否则只是装饰性选择）。
3. **不欠账**：不留「之后自然就知道」的空头承诺——源文件把「拿后续自然展开糊弄互动点」列为禁手。

### 玩家动机必须清晰
「玩家身份和到场动机必须清晰（新员工、应聘者、受托人、收到邀请的人等）。」动机不清 → 玩家第一句只能问「我是谁、我在哪」，这一轮就废了。

## 六、反面样本 → 正面改写

> 以下 5 组样本为**本文按上述规则自写**的教学示例，不对应任何具体作品，也不来自源文件原文；每组标注它违反的规则。

### 组 1 · 描写过满 + 替玩家动作（最常见的「无话可说」）

**反面**
```
雨下得很大。你站在门口，犹豫了一下才推开门。屋里很暖，混着旧木头和廉价
香薰的气味。她坐在靠窗的位置，黑发垂下来，指尖绕着杯沿。你觉得她很好看，
心里有点发紧。她抬起头，看着你，说：「你来了。」
```

**违反**：替玩家写「犹豫」「推门」「你觉得」「心里发紧」；环境三连均匀堆料；结尾空。

**正面**
```
雨把门口的台阶泡得发软。

窗边那张桌子上摊着三样东西：一份没签字的合同、一把湿透的折叠伞、一杯
已经凉透的茶。她没抬头，把茶往桌角推了推，推到你站的那一侧。

「伞是你的。」她说，「昨天那把。」

门口的风铃还在响，说明有人跟在你后面进来。
```

**改动点**：只写可观察事实；玩家位置用一张桌子和一句指认交代；结尾是「有人跟在后面」这个局面变化，否认 / 回头看 / 先坐下三种回应都成立。

### 组 2 · 人物介绍式罗列（设定表冒充嗓音）

**反面**
```
她叫叶清和，二十六岁，是一家旧书店的老板。她性格冷淡但内心温柔，说话
总是很简短，偶尔会露出孩子气的一面。她对陌生人戒备心很强，但一旦信任
一个人就会非常依赖对方。
```

**违反**：靠复述完整性情立人设；一句台词都没有；「冷淡但温柔」是标签不是设计。

**正面**
```
「这本不卖。」

她把书从柜台上抽回去，用袖口擦了一下封皮，才放回架子——够得着的那一层，
不是最里面。

「上面那层也不卖。」她补了一句，眼睛没看你，手在账本上写字，写得很慢，
一笔一笔压着格子走。
```

**改动点**：性情从三个具体动作（抽回、擦、放够得着的那层）里长出来；戒备用一句多余的补充台词表现；年龄与职业不出场，交给角色卡 `description`。

### 组 3 · 平淡日常开场（前三行没有拉力）

**反面**
```
早上八点，闹钟响了。你起床洗漱，吃完早饭就出门了。今天天气很好，街上
人不多。你走了一会儿，来到公司楼下。
```

**违反**：直接从平淡日常起手；无信息、无情绪、无互动空间；三句流水账。

**正面**
```
你是第七个到的人，但门卫只记得前六个。

工位上的显示器换过了。贴着的那张便利贴还在——不是你的字迹，上面只有
一行：「八点四十，别开灯。」

九点差四分，走廊尽头的会议室传来有人挪椅子的声音，只响了一下。
```

**改动点**：反常细节（门卫只记得前六个、便利贴上的陌生叮嘱、椅子只响一声）制造「为什么」，同时把到场动机（公司、新入职）与一个未解决问题一并放下。

### 组 4 · 世界观倾倒（把开场当设定页）

**反面**
```
这个世界分为三大大陆，灵气自七千年前的天裂事件后开始衰退。当前由九大
宗门共同维持秩序，其中以青云宗为首。修炼分为炼气、筑基、金丹、元婴等
境界。你是一个刚入门的弟子，资质平平。
```

**违反**：开场不是世界观摘要；信息量与当前一幕无关；玩家读完没有任何可做的事。

**正面**
```
考核的钟敲了一半就停了。

广场上两百多个新弟子还站着，没人敢动。执事握著名册的手垂在身侧，眼睛
盯着山门的方向——那里有一道很细的裂缝，正往下滴东西，滴进石缝里，
石缝在冒烟。

「炼气的都往后站。」执事说。他自己没动。
```

**改动点**：境界设定只出现「炼气」一个词，且是**现在必须听懂才能照做**的那一个；其余世界观归世界书条目。

### 组 5 · 结尾空问句

**反面**：`她看着你，问：「你怎么想？」` —— 把设局的活也推给玩家，玩家得先替你造出选项。

**正面**：`她把两份文件并排推过来，手压在左边那份上。「签哪份，你决定。不过我提醒你——右边那份，我已经签过名了。」` —— 仍是让玩家决定，但**选项、代价、一个不对称的信息差**都已摆在桌上。

## 七、与 `alternate_greetings` 的配合

- **基本契约**：`alternate_greetings` 是**多个入口**，玩家开局只选中一条；被选中的那一条必须**自身完整可玩**（源文件口径：「其余 `alternate_greetings` 照常写完整文案」），不能依赖主 `first_mes` 已交代过的内容。墨月对应 `first_messages[]`：逐项存 `output_path`（通常 `开场白/{index}.txt`），按顺序注册到 state，**顺序必须与创作规划一致**。风月引导页对应 `openings[]`：每条要有 `title`，`text` 是「完整开局前提」，且**只汇总选中的这一条**进导出消息。
- **主 `first_mes` 放占位符时**：可以只放一个占位符（`<TentacleReady>`、`<HkmOpeningSetup/>`、`<GuPCreatorImpl/>`、`[游玩指南]` 等），由 `[开场]/[替换]` 正则替换为表单；**此时其余 `alternate_greetings` 必须照常写完整文案**，给不想创角的玩家直接开局。
- **占位符与正则**：占位符与 `findRegex` 必须完全一致（含大小写与斜杠；建议 `/<XxxReady\s*\/>/g` 兼容空格）。表单正则 `markdownOnly: true` / `promptOnly: false`；两段式的「开始创建」正则加 `maxDepth: 1`，只在最新楼层渲染。自定义占位符**不会被打包自动追加**，须在末尾手动写入并手动注册替换/隐藏两个正则（共用同一 `findRegex`）。
- **多变体与变量**：额外开场白需要不同初始值时用 `initvar_override`（`开场白/initvar/{index}.yaml`，注册到 state，pack 自动嵌入 `<UpdateVariable><initvar>` 块）；默认开场白（`开场白/0.txt`）对应默认 `世界书/变量/initvar.yaml`。叙述里的时间、地点、关系、状态、好感、任务进度**必须与所选开场白的初始变量一致**——这是叙事式开场白的硬验收项。后缀：`.txt` 打包时自动追加 `<StatusPlaceHolderImpl/>`（状态栏锚点），`.md` 不追加；需要状态栏存 `.txt`，说明式存 `.md`。
- **表单式特例**：创角发生在聊天已打开之后时，`<initvar>` 只在「新开聊天」时被 MVU 读取，因此**必须用 JSONPatch 完整初始化变量**。配一条世界书协议条目（如 `[mvu_update]自定义开局更新指令`），触发条件「用户消息包含 `<OpeningConfig>`」，执行顺序：JSONPatch 完整覆盖 `/世界 /主角 /系统`（用 replace 给完整结构，禁止 insert 逐项添加）→ 校验数值与配置一致 → 再开始正文。

## 八、与系统提示 / 世界书的分工

一句话：**开场白管「这一次」，世界书管「每一轮」，系统提示管「怎么呈现」。**

| 层 | 承载什么 | 不该放什么 |
|---|---|---|
| **`first_mes` / `alternate_greetings`** | 这一次开局的现场：时间、地点、在场者、正在发生的变化、可接手的局面 | 文风合同、分析、教程、检查说明、世界书配置、标题包装、使用提示 |
| **系统提示 / 主提示词** | 权威规则与输出结构、平台层行为约束 | 具体剧情结果；与前置/后置词不一致的第二套限额 |
| **世界书 · 呈现方式（presentation）** | 叙事基调、文风要求、互动要求、写作约束；**写「如何做」不写「是什么」**，通常 200 字以内；`rephrase: true` 只写两三句特殊要求/消刻板印象 | 风格分析、长篇文论 |
| **世界书 · 阶段指导（stage guidance）** | 每阶段的 `goal / narration_focus / interaction / progression_boundary`，EJS 条件渲染只输出当前阶段 | 世界观复述、角色全文、单次事件桥段、固定剧情大纲 |
| **世界书 · 协议条目** | 教 AI 消费结构化用户输入（如 `<OpeningConfig>` → JSONPatch 初始化） | 玩法说明的散文 |
| **世界书 · 人物/地点/事件** | 按需触发的资料 | 本该在开场现场演出来的东西 |

三条容易踩线的分工：
1. **文风写在开场白里 = 占额度且不会被遵守。** 文风要求保留在对话和给子代理的指令中，开场白文件**只保存正文**。
2. **「如何呈现」写两遍 = 两套规则打架。** 开场白的旁白风格、世界书 presentation、系统提示不应该是三份不同的规矩；风月口径是主提示词管权威规则与输出结构，前置词读上下文，后置词做本轮落地检查。
3. **把设定塞进开场白以「确保模型看到」= 用最贵的窗口做最便宜的常驻。** 常驻归世界书 constant，阶段性归 stage guidance。

## 九、流程挂钩（墨月）

叙事式开场白由 `first-message-agent` 撰写，主代理传参与验收：

1. 读 `创作规划.yaml` 的 `first_messages` 数组，逐项处理。
2. **文风确认**：`style` 已明确或主代理已委托 → 同一轮直接成稿，**不额外增加一轮确认**；`style` 缺失或只有「细腻、沉浸、自然」等空泛表述 → 结合场景材料具体化；无法具体化时在自查摘要里报「需向用户确认文风方向」，**不自行虚构文风**。
3. 传入规划路径 + 索引（启用 MVU 时传 initvar 路径：有 `initvar_override` 传 override，否则传默认 `世界书/变量/initvar.yaml`）；子代理直接写入 `output_path`，返回文件名 + 实际字数 + 自查摘要，主代理再调 `check-agent` 检查正文。

**文风约定只保留会改变正文的内容**（六项，按用户实际要求压缩，不要求全出现）：叙述距离与观察中心 / 句子节奏、段落体量与信息密度 / 对话·动作·环境·心理各自承担什么 / 情绪与氛围怎样进入文字 / 用户明确排斥的写作习惯 / 用户指定的篇幅范围。

**唯一的问题原则**：没有文风方向时只问一个宽问题（「你希望这段开场白读起来是什么感觉」，或让她粘一小段自己喜欢的无关文字），**不一次发放视角、句长、辞藻、对白比例、节奏、氛围、禁词的完整问卷**。**修改纪律**：局部修改优先局部重写，不推翻已确认的文风与全部正文；若修改暴露文风合同本身有误 → 明确退回第一阶段重新确认，**不能暗中改变合同**。

## 十、自查清单

- [ ] **结构**｜前三行有拉力（悬念 / 反常细节 / 情绪拉力 / 未解决问题，至少一项）；玩家身份与到场动机清晰；结尾停在可接手处且不必是问句；至少三种合理回应成立（可回、有代价、不欠账）；无「后续自然展开」式空头承诺
- [ ] **边界**｜未写 `<user>` 的台词与内心话、主动动作、身体反应与感受、对人物的判断愿望与决定；未写进入场景后尚未由用户确定的过去行为
- [ ] **现场条件**｜`<user>` 的客观位置/身份/此前事实只作场景条件出现，未被顺势展开成行为或感受
- [ ] **信息量**｜背景只通过现场可观察或当前行动确实需要的部分进入；历史只留理解眼前变化必需的部分；人设通过选择与表达进入，不复述完整性情；只让当前真正参与这一幕的人出现
- [ ] **字数**｜符合 `word_count`（规划已指定时）
- [ ] **嗓音**｜对话有明确对象、欲求和回应；情绪在触发它的言行之后；无抽象情绪标签、过密比喻、相同句式和反复自问堆词；列举优先两项
- [ ] **出场**｜靠动作/对话/物件/关系反应，无人物介绍式罗列
- [ ] **一致性**｜叙述中的时间、地点、关系、状态、好感、任务进度与所选 initvar 一致
- [ ] **变体**｜主 `first_mes` 是占位符时，至少一条 alternate 是「直接开局」的完整文案
- [ ] **形式约束**｜说明式（如有）位于第 0 位、其后有真入口、存 `.md`；需要状态栏的叙事式存 `.txt`
- [ ] **正则**｜占位符与 `findRegex` 完全一致；表单正则 `markdownOnly: true` / `promptOnly: false`
- [ ] **变量**｜表单式卡片用 JSONPatch 初始化，未依赖 `<initvar>`
- [ ] **正文纯度**｜无文风合同、分析、教程、检查说明、标题包装、使用提示
- [ ] **注册**｜已注册到 state 的 `first_messages`，顺序与创作规划一致
