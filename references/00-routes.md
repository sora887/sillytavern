# 00 · 任务路由与流程闸门

> 这份文件决定「先读哪份参考、产出什么、什么时候必须停下来给用户看」。
> 默认路线是 **R1**；用户说的第一句话决定路线，不要混着走。

---

## 一、先判定路线

| 用户说什么 | 路线 | 必读参考（按顺序） | 首件产出 |
|---|---|---|---|
| 「帮我写张卡 / 做个角色」+ 有主题或人设雏形 | **R1 新建完整卡** | `20-character` → `10-worldbook` → `30-opening` → 需要时 `40-mvu-regex-ejs` → `50-format` → `60-quality` | `design-spec.md` |
| 「把这个小说/设定集做成世界书」/ 只给了文本 | **R2 世界书优先** | `10-worldbook` → `20-character` | 世界书条目表草稿 |
| 「我这有张卡 / 帮我拆开看看 / 改一下」 | **R3 存量卡改造** | `50-format`（拆包）→ `60-quality`（体检）→ 定点读对应章节 | 体检报告 |
| 「只改开场白 / 只加状态栏 / 只调人设」 | **R4 局部变体** | 直接读对应单篇（`30-opening` / `40-mvu-regex-ejs` / `20-character`） | 改动前后对照 |
| 「这张卡为什么不好玩」 | **R3 + `60-quality`** | `60-quality` → `30-opening` | 失效环节诊断 |

判据不够就**只问一个问题**（最多三个），问完立刻给方案，不要为凑信息反复追问。

---

## 二、四道闸门（R1 强制，R2/R3 按需）

### 闸门 0 · 需求定档

开写前必须锁定这五项，缺一项就问：

1. **卡的体裁**：日常向 / 剧情向 / 恋爱向 / 恐怖 / 战斗 / 悬疑
2. **玩家位置**：玩家是「被追求者」「同行者」还是「支配者」
3. **人物核心矛盾**：一句能复述的话（说不出就别写，先去 `20-character` 找）
4. **技术档位**：纯文本卡 / MVU 变量卡 / 带状态栏 UI 卡（三档成本差很多）
5. **交付形态**：只要文本方案 / 要可导入的 JSON / 要 v3 PNG

### 闸门 1 · design-spec 先过目

产出 `design-spec.md`，只写**决策**不写正文：

```markdown
## 核心命题
一句话：这个角色身上「说不通但成立」的地方是什么

## 人物骨架
- 表层（外人对她的判断）：
- 结构层（支撑她行为的东西）：
- 刺点（一处不合逻辑但有来源的偏差）：

## 信息分工表
| 信息 | 放哪 | 为什么 |
|---|---|---|
| 核心身份 | description | 模型每轮都读 |
| 生活细节 | 世界书 selective | 按需触发 |
| 说话习惯 | mes_example | 靠示例学语气 |
| 剧情推进 | 世界书 constant | 必须常驻 |

## 技术选型
MVU: 用/不用　状态栏: 用/不用　正则: 几条

## 预估
世界书 N 条 / 开场白 N 字 / 总 token 量级
```

**用户没确认这份 spec，不得进入正文写作。** 这是本技能最重要的一条红线。

### 闸门 2 · 分批交付

不要一口气生成整张卡。顺序：

```
人设字段 → 世界书条目 → 开场白 → (变量/状态栏) → 示例对话 → 打包
```

每批写完停一次，让用户看。一次性输出 5000 字卡片 = 返工成本极高，且质量必降。

### 闸门 3 · 机械验收

写完必须跑 `60-quality` 的硬伤清单。**不允许"我觉得写完了"就交付。**
能用脚本的用脚本（`scripts/check_card.py`），不能自动化的逐条人工过。

---

## 三、写作时永远同时在线的五条

1. **具体名词 > 形容词**。「温柔但疏离」是标签；「递东西时先把杯柄转向你」是设计。
2. **一处怪 > 十处美**。宁可一个说不通的细节，也不要满篇漂亮话（对齐 `personal-agent-skills` 的 Taste Core）。
3. **因果先于装饰**。任何设定都要能回答「她为什么会有这个」。答不上就删。
4. **密度要分级**。指定高密度区（核心场景）和安静区（过渡段），不要全篇均匀堆料。
5. **人物要像人不像模特**。有身体感、有坏习惯、有不想被看见的部分。

---

## 四、与 `personal-agent-skills` 的协作边界

| 场景 | 走哪边 |
|---|---|
| 写卡的中文文案、人设气质、"人味"判断 | **本技能** + 引用其 `taste-core.md` / `design-dislikes.md` 作为审美基准 |
| 卡面立绘、封面图、差分图的**提示词** | **`personal-agent-skills`**（本技能不出图、不写图像 prompt） |
| 要实际生成图片 | 用户明确要求时才走生图；本技能默认只交文本 |
| 角色卡的 JSON/PNG 打包 | **本技能** `50-format` + `scripts/` |

写卡文案的审美锚点（来自用户长期偏好，非本文档自创）：

- 结构基底要精致，但保留一处怪、一点危险
- 服装按真实结构：基础层 / 结构层 / 标志性延伸 / 配件系统，交代剪裁、材质、固定点
- 默认拒绝：无因果的钟表、链条、蝴蝶、玫瑰、粒子；形容词堆出来的"高级感"
- 复杂性局部化，不做全画面均匀堆料
