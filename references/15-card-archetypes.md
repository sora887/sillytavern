# 15 · 卡型判定与四类原型

> 用途：**动笔前先判型**。同一套方法论在四类卡上取舍完全不同——判错型，后面所有配置都白做。
> 本文依据用户提供的 5 张成熟卡实测（[Personal experiment] · 2026-11-07，样本留档在 `st-card-study/`），与九个上游仓库的方法论交叉校验。

---

## 0 · 三个问题定卡型

| 问 | 倾向 |
|---|---|
| 玩家主要是在「探索一个世界」还是在「和一个人相处」？ | 世界 → 设定集 / 长篇剧情；人 → 系统面板 / 角色互动 |
| 剧情是**预先写好**的（时间线、事件链），还是**即时生成**的？ | 预先 → 长篇剧情；即时 → 其余三类 |
| 卡的重头戏是**文字**，还是**界面**（面板/插图/表单）？ | 界面 → 系统面板；文字 → 其余三类 |

三问交叉后落到下面四类之一。**允许混合**（如「长篇剧情 + 面板」），但必须指定主型——主型决定字段取舍，副型只在它不冲突的地方追加。

## 1 · 四类原型的取舍表

| 维度 | ① 设定集型 | ② 长篇剧情型 | ③ 系统面板型 | ④ 角色互动型 |
|---|---|---|---|---|
| 一句话 | 世界是产品，角色是导游 | 时间线是产品，角色是演员 | 界面是产品，正文是燃料 | 性格是产品，界面是加分项 |
| `description` | **留空** | **留空** | 中长（写规则契约） | 中长（写卖点+玩家目标） |
| `first_mes` | 极短占位符 + alternate 存正文 | 占位符（创角表单/开局选择） | 中长，开场即面板契约 | 长（正文型）或 短+正则渲染 |
| 世界书规模 | 大（40–90 条），条件条为主 | 大（60–100 条），索引+时间线 | 小（10–20 条），规则为主 | 中（15–25 条），高频于正文 |
| 常驻占比（**按字数**） | ~50% | ~20% | ~40% | 常驻可 100% |
| 正文载体 | alternate_greetings | 世界书事件条 + MVU | 面板模板（XML/HTML） | `first_mes` 正文 |
| 必备装置 | 目录条目 | 索引 + 时间线映射 | 格式契约 + 自检条 | 成对标记正则 |
| 代表形态 | 山海经 | 无职 1.0.1 | 淫鬼驱魔录 | 女儿是本子画师 / 青云宗 |

### 各型的必做与禁做

**① 设定集型**
- 必做：一条常驻「目录」告诉模型有哪些条目可触发；条目按「分类 - 主题」命名；把文风写成条目（见 §3）。
- 禁做：把世界观塞进 `description`（会和条目重复，模型随机挑一份执行）；用 `mes_example` 教语气。
- 验收：随便问一个设定细节，模型能否在**不重开**的情况下答对；答错多 → 目录/触发词没做好。

**② 长篇剧情型**
- 必做：索引条目（角色速览/时间线索引）+ 时间线条目 + 变量规则条；`[initvar]` 默认禁用。
- 禁做：为单日事件建条目（用条目做「阶段概括」，只引用当前日期之前）。
- 验收：跨 20 轮后时间和人物状态是否自洽；原著/原设定事件是否被错转给玩家。

**③ 系统面板型**
- 必做：英文或中文的**格式契约条目**（字段顺序、分隔符数量、首尾标签）；一条「输出前自检」条；成对正则在正文上方渲染面板。
- 禁做：让模型生成面板 HTML（只让它输出占位符/字段串，HTML 交给正则）。
- 验收：连续 10 层是否每层都有面板、字段数是否稳定、有没有漏闭合标签。

**④ 角色互动型**
- 必做：长开场白（正文型）或成对标记正则（UI 型）；语气靠开场白示范，不靠字段描述。
- 禁做：把 UI 组件写进正文纯文本（用 `[标记]...[/标记]` 让正则接管）。
- 验收：聊 5 轮后角色说话是否「还是同一个人」；界面组件是否稳。

## 2 · 位置三档：常驻往哪放

实测中成熟卡把常驻条目分三档摆，不是一律 `depth=4`：

| 档 | position / depth | 放什么 | 理由 |
|---|---|---|---|
| **法则层** | `pos=0`（before char） | 世界法则、硬约束、目录、图池 | 在角色设定之前，作为「环境前提」先立住 |
| **主控层** | `pos=1`（after char） | 主控指令、叙述准则、审查规则 | 紧跟角色设定，管「怎么演」 |
| **生成点层** | `pos=4` + `depth=0` | 变量格式、输出格式强制块 | 贴着最近对话，服从度最高 |
| **细则层** | `pos=4` + `depth=2~4` | 条件条目、文风细节 | 离生成点近，但不占最优先 |

补充口径：`pos=5/6`（↑EM/↓EM）用于示例消息区；`depth` 大于 4（如 9/10）实测也有人在用（青云宗 31 条 `depth=9`），效果是「更贴底部」，但跨平台裁剪行为 `[待核]`，没有实测就不要照抄。

## 3 · 常驻预算：按字数算，不按条数

实测里「常驻 18/64 条」听起来只占 28%，但按字数算是 **52%**——**条数口径会骗人**。

| 卡 | 常驻条数 | 常驻字数占比 |
|---|---|---|
| 山海经 | 18 / 64（28%） | **52%** |
| 无职 1.0.1 | 14 / 91（15%） | 21% |
| 青云宗 | 20 / 50（40%） | 47% |
| 淫鬼驱魔录 | 6 / 15（40%） | 42% |
| 女儿是本子画师 | 18 / 18（100%） | 100% |

纪律：**报预算一律报字数**。常驻字数超过总字数 60% 时，先问「这些东西每轮真的都需要吗」，而不是继续加常驻。

## 4 · 四个可直接复用的结构招

### 4.1 「其一 / 其二」拆条

同一个对象拆成两条，同 `keys`、同 `depth`，分别放不同侧面：

- `本形卷 - 驺吾其一`（505 字）：图鉴式形貌、体量、习性
- `本形卷 - 驺吾其二`（318 字）：性情、忌讳、祅祥数值

好处：触发一次拿两段，但作者可以单独改其中一段；不会出现「形貌写得很好、性格挤在末尾两句」的偷懒。

### 4.2 索引条目（最低成本的防幻觉装置）

一条常驻小条目，只写「有哪些人/哪个时段/有哪些卷」，不写细节：

- `角色速览`（2406 字，40 人各三行）
- `基础 - 山海经 - 目录`
- `画师与本子列表`

作用：模型先知道自己有什么，再去触发详情。**没有索引，条目越多幻觉越多。**

### 4.3 时间线 key + EJS 映射

时间线条目名做成机器可读的 key，再用 EJS 按当前变量选择：

```ejs
<% const key = getvar('stat_data.世界.时间线关键词'); %>
<% if (key) { const t = await getwi(null, key); } %>
```

配套纪律：时间线条目写「阶段概括」，不写单日事件；只允许引用当前日期之前的部分。

### 4.4 禁用条目 = 可选模块池

`disable: true` 不只是「关掉某条」——成熟卡把它当**模块化分发**手段：

- 青云宗 50 条里 **31 条禁用**：随卡分发的扩展卷/DLC/替换版本，玩家自己开
- 无职 91 条里 13 条禁用

做法：禁用的模块条首行写 `<!--【手动条目】启用条件：… -->`；`keys` 收窄为结构性词；包里保留全部模块，卡照样能玩。

## 5 · 两条实测反教程

| 常见教程 | 实测 |
|---|---|
| `personality` / `scenario` / `mes_example` 必须写满 | 5/5 张成熟卡**全空**；语气靠世界书文风条 + 开场白 |
| 「不得替玩家写动作」 | 山海经大量代写玩家动作（`{{user}}点了点头`），只封**一个命门**：「AI 不得代替 {{user}} 翻阅《山海经》，仅当用户下达明确翻书指令后方可输出」 |

结论：禁令要**收窄到具体动作**，不要写成「不得代写玩家」。封面太大 → 叙事呆板；不封 → 玩家被夺权。封一个关键开关即可。

## 6 · 判型自查

- [ ] 能一句话说出这张卡的主型（四类之一）
- [ ] `description` 的写法与主型一致（不是「我想写就写」）
- [ ] 常驻预算按字数报过，且知道超没超 60%
- [ ] 有索引条目（①②型必须，③④型建议）
- [ ] 明确写了「哪个动作不许 AI 代做」（只写一个）
- [ ] 该型的必做装置都齐了（见表 §1）
