# 20 · 人设：调色盘路线 vs 人物生境路线

> 人设不是「把九套方法论平均一下」。本项目里存在两条**互斥**路线：
>
> - **调色盘（personality-palette）**：把性格拆成可调参数 —— 底色 / 主色调 / 点缀 / 衍生，再叠 三面性、二次解释、多阶段。
> - **人物生境（habitat）**：反模板、反预写答案 —— 基础信息 / 生活结构 / 人物性情 / 场景表达 / 穿衣风格。
>
> 选定一条就不要再套另一条的骨架。混用 = 同一个人物被两套结构各写一遍，模型收到互相打架的约束。
>
> **标注约定**：标 † 的是本文建议值（源文件未规定字数）；标 [待核] 的是源文件未给出、需要另查的部分。凡是源文件写死的规则，一律给出出处。

## 0 · 先做路线判定（这一步不能跳）

### 0.1 判定表

| 用户带的材料 | 路线 | `project.character_route` | 首件产出 |
|---|---|---|---|
| 已成型的人设构想：知道她是什么人，只想成卡 | 调色盘 | `palette` | 性格调色盘 |
| 只有零散构想 / 片断画面 / 明确要求「AI 不许替我决定人物」 | 人物生境 | `habitat` | 材料包 `materials/*.md` |
| 只说「写张卡」，没给人物 | 先回 `00-routes` 闸门 0；仍判不出就先跑 intake-router | 待定 | `design-spec.md` |

判定分水岭不是「人物复杂不复杂」，而是**谁有权定义人物**：用户已经说出她是什么人 → 调色盘，AI 做拆解与引导；用户只给线索且要求 AI 不替他决定 → 人物生境，AI 只做整理与提问。

### 0.2 `character_route` 的硬规则（源：moyu-cards `tavern-cards/SKILL.md` 人物条目创作路线判定段）

- 字段：`创作规划.yaml` 的 `project.character_route`，取值 `palette` | `habitat`，**缺省视为 `palette`**。
- **入口一次判定**：design 阶段判定一次并记录，content 阶段不再改判。
- **同一项目内不混用两条路线**。
- 两条路线的最终产物都注册进同一 `entryManifest`，不是两套工程。
- 生境路线的用户材料由 design 阶段的 `intake-router` 分流成材料包（写入 `cards/{Project}/materials/*.md`，七类标签）；已有成型构想时不启用 intake-router。

### 0.3 混用的四个症状（本文归纳，用于事后体检）

| 症状 | 根因 |
|---|---|
| 同一个人物既有「衍生一/二/三」又有「生活结构/性情」两套正文 | 两条路线的产物都被注册进 `entryManifest` |
| 模型对同一行为给出两种解释：一处「她这样是因为…」，一处「她往往…」 | 三面性/二次解释的「为什么」与生境的「不写因果解释」冲突 |
| 人设条目越写越长，删不动 | 调色盘要求「每性格 2-3 条衍生」，生境要求「用户没想过的可以空着」 |
| 用户说「AI 又在替我编」 | 走的是 `palette`，但用户诉求是 habitat 的「只以用户确认内容为事实」 |

## 1 · 路线 A：调色盘 / personality-palette

### 1.1 四层结构

| 层 | 写什么 | 数量 | 避免 |
|---|---|---|---|
| **底色** | 最深层的性格基调，始终存在但不一定最明显 | 1 个 | 写成剧情设定；底色不随阶段变化 |
| **主色调** | 日常最突出的性格，别人的第一印象 | 1-2 个（源定） | 与底色重复 |
| **点缀** | 特定条件下才出现的隐藏性格 | 0+ 个，可以没有 | 为凑结构硬加 |
| **衍生** | 每个性格色在具体场景里的表现 —— **这是核心** | 每性格点至少 2-3 条（源定） | 抽象定义、形容词复述 |

### 1.2 衍生的七条约束（源：`personality-palette.md`）

1. **衍生由用户自己写，AI 只引导**。原文理由：AI 写的衍生永远逃不出资料库与逻辑的关联性，只有人才能把毫无关联的性格组合在一起。
2. 写具体场景和行为，不写抽象定义。
3. 要写出「这个角色才会有的」动作、说话方式、与人来往的节奏 —— 遮住名字也能分清是谁。
4. 可以写看似矛盾的内容，人就是复杂的。
5. 可以跨性格关联，也可以关联其他角色。
6. **不通顺的句子、重复的内容不要改** —— 这些可能是角色活过来的关键。
7. 引导时不替代：用户写完，AI 只做自查，不改写。

### 1.3 落盘格式

```text
性格调色盘:人的性格就像调色盘，叛逆是底色，热情与不拘一格是主色调，由多种性格衍生组合而成才是活生生的人
主色调：热情、不拘一格
底色：叛逆
性格点缀：依赖

热情衍生一：在对待摇滚这件事上有着用不完的精力，无论是在创作、演唱还是练习，都会用上百分百的热情。
热情衍生二：在热情褪去后的几天里，她会懒散地窝在沙发上或桌子上，像没电了一样睡觉或发呆。
依赖衍生一：在红美玲面前，她会放下叛逆和不拘一格的那一套，暴露她内心深处的依赖。
```

- 首行固定句式 `性格调色盘:人的性格就像调色盘，…`；字段行顺序 `主色调：` → `底色：` → `性格点缀：`；衍生行 `{性格色}衍生{一/二/三}：{具体场景}`。
- 每条衍生 †建议 1-3 句、只写一个场景，不要在一行里塞三种场合。

### 1.4 延伸一：三面性 / tri-faceted（可选）

**前置**：调色盘已完成。三面性是调色盘的延伸，没有调色盘的它是空壳。**本质**：不是三种性格，而是同一个发动机在不同路况下换档位；面数由角色决定（2-N 面，多数人拆到 3 面）。

| 部件（缺一不可） | 写什么 | 量 |
|---|---|---|
| 触发条件 | 什么情况下这张面启动 | 1-3 条 |
| 能量状态 | 消耗多少精力、稳定不稳定 | 1-2 句 |
| **语料** | 这张面里她怎么说话 | 5-10 句纯对话（源定） |
| 身体行为模式 | 这张面里身体怎么动 | 1-3 句 |
| 功能 | 在保护什么、解决什么问题 | 1-2 句 |

**四条硬约束**：语料必须**从调色盘移到三面性里**（否则重复，且混在一起 AI 会搞乱）；语料**只保留纯对话**，删掉混入的动作/表情/心理描写；只写「怎么运作」不写「为什么」（那是二次解释的活）；至少写两组过渡 + 一些渗透细节 —— 过渡 = 最常见/最剧烈切换路径 + 中间状态，渗透 = 一面运行中另一面的元素泄漏（泄漏是角色最真实的瞬间）。

**不需要三面性的判断**：找不出两个以上「压力性质截然不同」的场景就不要硬拆；硬写的危害是 AI 把连贯角色切成几块演，像在换频道。

**常见错误词**：`因为` `本质上` `其实` `内心` —— 出现即是二次解释混进来了。

### 1.5 延伸二：二次解释 / rephrase（源：`rephrase.md`）

- 定义：作者对角色的**终极注释**，作用是防 AI 用资料库补全。
- 与「演绎指导」相反：演绎指导让角色变成 AI 的理解，二次解释把人拉回作者的理解。
- 每条围绕一个性格点，只写四类内容：真正含义 / 它不是什么 / 何时出现、何时不出现 / 与其他性格的关系。
- 必须用户自己写；不通顺、重复保留原样。

```text
对角色的理解与思考:
  关于[性格点]: | …
  总结_性格调色盘: | …
```

### 1.6 延伸三：多阶段 / multi-stage

**前置**：`创作规划.yaml` 的 `characters[].personality.stages` 与 `ejs.entries[].stages` 的 condition 已定。

| 规则 | 说明 |
|---|---|
| 底色不随阶段变 | 变的只有主色调的表现方式与衍生 |
| 阶段专属衍生 = 该阶段**新出现**的行为 | 不是上一阶段的升级版 |
| 通用衍生跨阶段始终存在 | 放在所有条件外 |
| 同一行为的多阶段差异 | 写进二次解释，不复制衍生 |
| 阶段边界值不重叠、不遗漏 | 边界值是机械事实 |

落盘就是 EJS（源文件原样）：

```ejs
<%_ if (affection < 10) { _%>
…
<%_ } else if (affection >= 10 && affection < 30) { _%>
…
<%_ } _%>
```

**与三面性的区别**：阶段变化来自人物关系随剧情推进，不是场景切换。

### 1.7 编写顺序（源：`composition.md`）

```text
基础信息（必写）→ 性格调色盘（必写）→ 三面性（可选）→ 二次解释（必写）
```

5 个以上角色时，先写 `角色速览.yaml`。

## 2 · 路线 B：人物生境 / habitat

### 2.1 五专项与拼接顺序

打包器按此顺序拼接**实际存在的**最终标签，**不增加统一总标签**：

```text
基础信息 → 穿衣风格（如有）→ 生活结构 → 人物性情 → 场景表达
```

- 外层标签形态 `<角色名_基础信息>`；整理稿 `<角色名_基础信息_整理稿>`，用户确认后去掉 `_整理稿` 后缀写最终文件。
- 最终文件只留人物：不留问题、教程、配置、测试说明；**空栏目直接省略，不输出占位符**。
- 通用边界（五专项都适用）：只以用户亲自写出、粘贴、明确确认的内容为事实。**模型实测正文里的临时发挥、诊断包里的假设，都不能倒灌成人设。**

### 2.2 材料分流：七类标签（源：`tavern-design/references/moyue/intake-router.md`）

| 标签 | 去向 |
|---|---|
| `<人物生境_基础信息材料>` | 基础信息页签 |
| `<人物生境_生活结构材料>` | 生活结构页签 |
| `<人物生境_人物性情材料>` | 人物性情页签 |
| `<人物生境_场景表达材料>` | 场景表达页签 |
| `<人物生境_穿衣风格材料>` | 穿衣风格页签（可选） |
| `<人物生境_长期人设外材料>` | 共同世界规则、当前剧情、会变化的关系阶段、此刻地点与任务、使用者资料、输出格式 |
| `<人物生境_待归类材料>` | 含义不足或互相矛盾、无法确定去向 |

intake-router 的铁律：**只分类，不创作、不补全、不直出人物设定**；长期人设外材料只负责被安全移出，不得删除，也不得强塞进四个专项。

### 2.3 五专项字段表

| 专项 | 只回答什么 | 写什么 | 字数† | 明确不写 |
|---|---|---|---|---|
| **基础信息** | 这个人是谁，以什么身体、身份、经历和长期社会坐标存在 | 身份坐标、身体锚点、客观经历、社会关系坐标 | 300-500 | 性情推导、会变化的状态、参考图的一次性光线/动作/表情 |
| **生活结构** | 主线剧情和重要关系没触发她时，她原本生活在什么里面 | 长期投入的事务、真正掌握的能力、反复来往的人与地方、不能随意丢下的责任、可调用资源、持续限制行动的现实条件 | 300-500 | 每日作息、爱好列表、随身物品清单、房间陈设、完整职业百科、按年份小传 |
| **人物性情** | 她怎样理解事情、真正在意什么、怎样看待自己 | 赋予事情的意义、在意与互相牵动、自我认识、长期倾向 | 300-600 | 固定台词、固定动作、情绪流程、场景结局 |
| **场景表达** | 性情怎样变成发言与行动（**窄而可选**） | 发言目的、表达体量、如何使用身体与环境、没人推动时是否仍继续自己的事 | 0-300；前三够就省略 | 表面形式描述（「温柔语气、简短句子、偶尔停顿」） |
| **穿衣风格**（可选） | 她通常依据什么作出穿衣选择 | 选择依据、场合变化逻辑、明确的例外（制服/宗教服饰/装备） | 0-200 | 服装类别库存、数量/品牌/颜色/款式清单、每场景一套、「总是穿某件」的固定镜头、当前这一幕的穿着 |

### 2.4 三个共性约束（最容易违反的）

**① 静态 / 动态分离（基础信息）**：可以留已发生且不会失效的历史；「目前独居」「刚刚接任」「正在住院」「尚未认识某人」「现在只是朋友」这类会变化的状态必须移出长期人设；不得用「以后不要复位」打补丁。

**② 独立性的判断标准（生活结构）**：不看重要关系占多少篇幅，而看重要人物不在场时她是否仍有正在进行的事、责任、关系、欲望与行动原因；但**不得为证明独立而削弱相依为命的关系**。

**③ 性情词只是入口（人物性情）**：问题不在用标签，而在模型只能从标签得到最公共的联想，所以必须写出该词在她身上**怎样影响理解和选择**；用「往往、容易、更愿意、很难、除非」，**只有绝对边界才用「永远、绝不会」**；关系不能替代整个人 —— 暂时拿走这段关系，她仍应对自己、责任、失败、自由、陌生人拥有能驱使行动的方向；**不得强求**创伤、核心矛盾、反差、隐藏人格、多面切换。

**场景表达的四个反模板点**：发言是为了完成事情（争取结果/拒绝安排/讲清事实/安慰/追问/宣布决定/鼓舞/掩饰动摇/结束纠缠）；不善言辞的人可以为目标完整解释，健谈的人悲伤时可能突然无话；情绪有经过但无固定流程；身体不应永远缩在目光、嘴角、手指、衣角 —— 人物拥有完整身体与可利用空间，可进入/退出/接管/修复/打破/保护。沉默与失败仍是表达；不得把角色修成永远克制、精准、稳定、清醒的机器。

### 2.5 轻量 NPC（habitat 版，源：`npc-light-habitat.md`）

- 用户只给几句话时，直接补足产出 `<姓名_基础信息>`，**不发放资料表**；最小四作用 = 身份坐标 / 生活抓手 / 性情方向 / 进入方式（不是四个栏目）。
- **劣质原型拦截**：高冷、冰山、天才、精密、绝对理性、永远冷静稳定克制 —— 不能成为核心定义，也不能进最终工件。也不许同义改写继续同一种人物（「高冷」→「疏离寡言」、「天才」→「超凡头脑」、「精密」→「每一步都毫无偏差」）。
- 能力只能落实为**明确领域中的实际结果、可调用经验与真实边界**，不能推出人格、荣誉、全知、永不失败。

### 2.6 实测与回流（源：`test-diagnosis.md`）

六项循环：原始构想 → 人设起点分流 → 四专项 → 组合 → 干净空卡实测 → 本条目诊断 → 回流到分块 → 再实测。

| 来源（必须分开） | 地位 |
|---|---|
| 用户已确认的人设事实 | 唯一可继续作为人物事实 |
| 模型某次正文临时生成的内容 | 输出证据，不得写回人设 |
| 用户观察与不满 | 决定优化目标 |
| 诊断假设 | 必须交回专项确认 |

诊断顺序：事实误认 → 是缺生活还是没被调用 → 是否落回公共性格模板 → 是否只剩一种语气/动作/体量（文风压过人物）→ 是否反复穿同几套 → 原设是否过重/重复/错位/预写答案 → 问题是否其实来自世界、剧情、开场、用户输入、模型、预设、格式。

优先处理顺序：`不修改继续观察` > `删除` > `迁移` > `合并重复` > `缩短` > `回专项确认一个缺失方向` > `改外部条件`。

回流标签：`<人物生境_基础信息回流>` / `_生活结构回流` / `_人物性情回流` / `_场景表达回流` / `_穿衣风格回流` / `_长期人设外回流`，字段固定为 用户观察 / 实测证据 / 原设相关内容 / 诊断假设 / 对应分块需要讨论。单次输出是**线索不是定论**，优先用陌生场景复测。

## 3 · 可直接落字段的产出规格

### 3.1 世界书人物条目（源：worldbook-skill `character-guide.md` 结构 + `character-card-guide.md` 分条目原则）

格式：XML 标签独占一行包裹 YAML；2 空格缩进；列表与键值对优先，不写散文段落。

| 字段 | 写什么 | 字数 | 避免 |
|---|---|---|---|
| `name` / `name_en` | 中文名（English Name） | 1 行 | 谐音玩梗式假名 |
| `age` | 年龄 + 身份定位 | ≤25† | 只写数字 |
| `gender` | 男/女/其他 | 1 词 | — |
| `nicknames` | 称呼 + 谁这么叫 | 3 个以内† | 无归属的绰号堆 |
| `appearance.height/weight` | 数值 + 单位 | — | 模糊形容 |
| `appearance.hair` | 发型/发色/发质/长度，**只写特征不写美感** | **30 字以内**（源定） | 「如丝绸般」 |
| `appearance.eyes` | 瞳色/眼型/眼神特点，写特征不写比喻 | **30 字以内**（源定） | 「眸如星辰」 |
| `appearance.skin` | 只写偏离默认的特征 | **20 字以内**（源定） | 「白皙」「吹弹可破」 |
| `appearance.build` | 体型/体态 | **20 字以内**（源定） | 「身材匀称」 |
| `appearance.clothing` | 分场合 2-3 条 | 每条 ≤20† | 全身穿搭清单 |
| `appearance.distinguishing` | 标志性特征、异于常人处、第一印象 | ≤40† | 「气质优雅」 |
| `appearance.voice` | 声线/说话风格/不同情绪下的语气变化 | ≤40† | 「声音很好听」 |
| `personality.core_drive` | 最想要什么、最怕什么，一句话 | 1 句 | 两段人生哲学 |
| `personality.traits` | 特征 **+ 行为依据** | **10-15 条**（源定） | 纯标签（「她温柔」） |
| `personality.likes/dislikes` | 具体事物，句号分隔 | 各 4-8 条† | 抽象（「喜欢美好的事物」） |
| `personality.habits` | 习惯性动作、行为模式 | 3-6 条† | 与 traits 重复 |
| `personality.hidden_self` | 不轻易示人的一面；表里矛盾的解释 | 1-4 条† | 用「其实是」做二次解释 |
| `background` | 只写「改变了这个人」的关键事件 | ≤150† | 流水账、童年可爱 |
| `abilities[].effects` | 写做了什么 + 限制/代价 | 每条 2-4 项† | 「威力强大」 |
| `relationships[].detail` | 怎么认识 + 现在怎么互动 + 特殊设定 | 每条 ≤80† | 「感情深厚」 |

**三条截断判断**（源：`rules.md`）：遮住名字能否认出是谁；删掉这条角色会不会变；每条是否只讲一件事（**一句一意**，写完一个态度就停）。

### 3.2 性格必须独立成条目

性格**不写在基本信息里**。混在一起的后果（源原文）：AI 读到基本信息就调用性格标签，后面的性格条目全在打架。

```yaml
<{{角色英文名/拼音}}_personality>
MBTI: xxxx
核心驱动力: 一句话
性格特征: [特征——行为依据, …]
深层心理: [不轻易示人的一面, …]
喜欢: 具体事物。用句号分隔。
讨厌: 具体事物。
习惯动作: 具体行为
</{{角色英文名/拼音}}_personality>
```

`character-card-guide.md` 的版本：`description` 字段为空，角色全部信息进世界书条目，人物设定条目与性格条目分开存储。

> **两套写法冲突提醒**：worldbook-skill 要求条目内容自带 XML 标签（`<character>` / `<X_personality>`）；moyu `conventions.md` 要求**内容文件本身不加标签**，XML 标签只在 `contents` 注册时由外层片段添加，否则打包重复。二者不能叠加。[待核] 以本项目 `50-format` 的打包脚本为准。

### 3.3 调色盘路线专属字段

| 字段 | 写什么 | 字数 | 避免 |
|---|---|---|---|
| 底色 | 1 个性格基调 | 1 词 + 1 句 | 剧情目标 |
| 主色调 | 1-2 个，第一印象 | 1 词 + 1 句 | 与底色同义 |
| 性格点缀 | 0+ 个，含触发条件 | 每点 1 句 | 硬凑 |
| 衍生 | 具体场景与行为 | 每点 2-3 条，每条 1-3 句 | 抽象定义、写成第三人格 |
| 二次解释 | 含义 / 不是什么 / 何时出现 | 每点 ≤5 行† | 「本质上」 |
| 三面性语料 | 纯对话 | 每面 5-10 句（源定） | 混入动作/表情/心理 |

### 3.4 NPC 与角色速览

**NPC**（源：`npc.md`）：围绕**功能**设计，不写调色盘/三面性/二次解释；每个 NPC 独立文件。功能 → 要写的字段：推动剧情 → 关键行为和决策点；提供信息 → 专业领域和知识范围；制造冲突 → 对立动机和行事方式；日常互动 → 生活习惯和互动场景。外貌 1-2 个最显眼特征 + 一句话整体印象；性格 2-3 个核心关键词，但要写具体行为不写标签；与 `<user>` 的关系是 NPC 最重要部分，写具体画面；语言特征含说话风格、口头禅、5-10 句典型纯对话语料。

**角色速览**（源：`character-catalog.md`）：是索引不是人设。必填姓名/性别/年龄，可选身份/职务/班级/关系；**5 个以上角色才写**；排序 `<user>` 最前 → 主要角色 → NPC。

## 4 · 反 AI 味写法

判断基准一句话：**遮住所有修饰词，句子的信息量不变 → 修饰词是冗余的 → 删。**

### 4.1 四个病灶与替代

| 病灶 | 症状 | 反面 | 替代写法 |
|---|---|---|---|
| **形容词堆叠** | 三个词说同一件事；形容词代替事实 | 「精致的脸蛋，白皙的皮肤，桃花眼，柳叶眉」 | 换成只有她才有的具体特征：「猫眼，笑起来弯成月牙」「左手食指和中指有弹吉他磨出的茧」 |
| **万能句** | 放谁身上都成立；作者直接告诉读者该感受什么 | 「身材匀称，亭亭玉立」「空气中有一种说不清的紧张感」 | 具体名词 + 可测量事实：「168cm，偏高，手臂有吉他练出的肌肉线条」；环境自己说话：「墙上的时钟咔咔走了四下」 |
| **无因果细节** | 细节与人物没有因果关系，只是好看 | 「她喜欢钟表/链条/蝴蝶」 | 因果先于装饰：任何设定都要能回答「她为什么会有这个」，答不上就删 |
| **状态栏依赖** | 情绪、关系、处境只写在变量/状态面板里，正文看不到 | 正文只写「她很生气」，靠 statusbar 交代好感度 | 状态栏只放**可计算的数值**（体力/好感/物品），人物的**态度与关系变化必须落在正文的动作上**（捏皱的收据、递水时不看你） |

### 4.2 三条正文明令禁律（源：`character-card-guide.md` 4.3）

1. **不写作者视角的解释性修饰**。角色低头就是低头，不附加「她看起来很难过」。
2. **不用解释性比喻补充白描**。写了「手在抖」就够了，不需要「像一片落叶」。
3. **不描写不存在的事物**。user 没看到的不能写；角色此刻没在想的东西不能写。

### 4.3 机器可扫的禁词（源：`composition.md` 机械自检正则，原样）

```text
——            （破折号）
似乎|仿佛|宛如|如同|几乎|近似
不是.*?(而是|只是)
极其|极大
本卡|写作要点|暂不展开|素材池|戏剧用途|核心冲突_
[A-Za-z]{3,}   （中英混杂，人工排除合规项）
```

豁免：EJS 语法、A/B/C/D 时代代号、半角连字符。

配套的八项人工检查（`rules-check.md`）：绝对零度、八股化、具体性、假性主体与远距离叙事、翻译腔、元叙事、跨条目重复、跨条目引用。**注意**：常见动作词不算八股，不要矫正过度。另：本文模板里 `特征——行为依据` 中的 `——` 是结构分隔符，写在正文散文里才被禁。

### 4.4 改稿的三档力度（源：charcard-workshop `rewrite-natural-prose`）

| 档位 | 允许的改动 |
|---|---|
| 轻润色 light（默认） | 去填充词、去重复、去拗口；保留信息顺序与作者声音 |
| 结构改写 structural | 重排句段、合并重复、强化重点；保留主张、事件、约束 |
| 深度重写 deep | 在既定视角与文体内重建表达与节奏；事实与 canon 不动；新增事件需用户创作简报 |

**绝对不动**：`{{user}}` 等宏、`stat_data.*` 变量路径、EJS、正则、JSON 键、ID、代码。「让句子生动」不是新增动作、动机或事实的许可。

## 5 · 人设 ↔ 世界书 ↔ 开场白：信息分工

### 5.1 分工表

| 信息 | 放哪 | 触发 | 为什么 |
|---|---|---|---|
| 姓名 / 年龄 / 身份 / 外貌特征 / 关系 | 世界书人物条目（基础信息） | constant 或 selective（见 `10-worldbook`） | 模型每轮都需要可查的身份锚 |
| 性格 / 性情 | **独立性格条目** | selective | 混进基础信息 → 读到身份就调性格标签，条目互相打架 |
| 世界规则 / 势力 / 地点 / 历史 | 世界观条目 | 按 `10-worldbook` | 公共世界，不该由人物条目承载 |
| 此刻的时间 / 地点 / 光线 / 角色正在做什么 | **开场白** | 一次性 | 属于「这一刻」，不该固化成长期人设 |
| 数值状态（好感 / 体力 / 关系阶段） | MVU 变量 + 状态栏 | 每轮更新 | 变量给模型算数，不承担讲戏 |
| 说话语气 | `mes_example` 示例对话 | 常驻 | 靠示例学语气，比一堆形容词可靠 |
| `description` | 为空（`character-card-guide.md` 路线） | — | 角色信息全部进世界书条目 |

### 5.2 三处重复的判定

同一事实同时出现在「人设条目 / 世界书条目 / 开场白」，模型会拿到三份略有差异的版本，然后随机挑一份执行。纪律：

- 人设写**长期成立**的东西（她是谁、她怎么理解事情）。
- 世界书写**身外**的东西（规则、地点、事件、别人的信息）。
- 开场白只写**这一刻**（时间、地点、她现在在做什么），且**不写人设里已写过的外貌清单**。
- 性格条目与三面性语料之间也不许重复：语料必须从调色盘**移出**，不是复制。

### 5.3 开场白的所有权

- 五步锚点（`character-card-guide.md`）：时间+地点+环境氛围 → 角色状态 → user 处境 → 互动契机 → 开放式结尾；启用 MVU 时末尾加 `<StatusPlaceHolderImpl/>`。
- 互动契机由**角色主动**递出，结尾停在等 user 接的位置；**不预设 user**（不写 user 的外貌/性别/性格/房间/经历/情绪）。
- 一次给 2-4 个 alternate_greetings，差异要落在时间/氛围/互动方式/空间关系，而不是换几个形容词。
- 开场白**不承担**人设职责：人设没写清的东西不要指望开场白补；开场白补的东西不能回流成人设事实。

| 范围 | 必须过 |
|---|---|
| **通用** | ① `project.character_route` 已写入 `创作规划.yaml`，全文只有一条路线的结构 ② 遮名测试：遮住名字能认出是谁 ③ 删词测试：删掉修饰词信息量不变 ④ 禁词正则跑过（`——` / `似乎\|仿佛\|宛如\|如同\|几乎\|近似` / `不是.*?而是` / `极其\|极大` / 元叙事词）⑤ 无占位符（「某城市/某学校/某组织」换成具体名称；不确定就问，不捏造）⑥ 性格已从基础信息分离为独立条目 ⑦ 开场白里没有人设的外貌清单 |
| **调色盘** | ① 底色/主色调/点缀完整，主色调 1-2 个 ② 每性格点至少 2-3 条衍生，且写场景与行为 ③ 衍生是用户写的，AI 没代写；用户原句的不通顺与重复保留 ④ 三面性（如写）每面五部件齐全，语料纯对话 5-10 句且已从调色盘移出 ⑤ 三面性里没有「因为/本质上/其实/内心」⑥ 二次解释每条围绕一个性格点、写四类内容 ⑦ 多阶段：底色未变、阶段专属衍生是新行为、边界不重叠不遗漏 |
| **人物生境** | ① 五专项齐全，顺序 基础信息 → 穿衣风格 → 生活结构 → 人物性情 → 场景表达 ② 空栏目已省略，无占位符 ③ 静态/动态分离完成，会变化的状态已移出长期人设 ④ 没有写入模型实测正文的临时发挥 ⑤ 性情部分没有固定台词/固定动作/情绪流程 ⑥ 生活结构能回答「重要人物不在场时她在做什么」⑦ 穿衣风格写的是选择依据，不是衣柜清单 |
